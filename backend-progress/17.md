# 17. Vector Embeddings & Semantic Indexing (Qdrant)

**Status:** ✅ Done

- **New embedding stage:** When transcription completes *with speech*, `transcript.worker.ts` enqueues a `"generate-embeddings"` job on the new BullMQ `embeddings` queue — in parallel with the AI-summary job. A silent video is marked `vectorIndex.status = "skipped"` instead.
- **Provider-aware embeddings (`EmbeddingService`):** Gemini (`gemini-embedding`, 768-dim) and OpenAI (`text-embedding-3-small`, 1536-dim) return raw vectors; Ollama/default returns a Qdrant **server-side inference** config (MiniLM, 384-dim) so no local embedding model is required.
- **Dimension-scoped collections:** The Qdrant collection name embeds the vector dimension (`video_transcripts_<dim>`), so switching AI provider lands in a *separate* collection rather than colliding with — or forcing a destructive re-index of — vectors stored at another dimension.
- **Chunk-and-upsert (`embedding.worker.ts`):** Transcript segments are grouped into ~500-char, timestamp-preserving chunks (`chunkTranscript`); the worker ensures the collection and a `videoId` payload index exist, embeds each chunk, and upserts points keyed by `videoId` (with `start`/`end`/`text` payload for later retrieval).
- **Model extension:** Added the `vectorIndex` sub-document (`pending → processing → completed | failed | skipped`) to `IVideo`, tracked independently of `video.status`. Failure is marked only once BullMQ retries are exhausted.
- **Config & tooling:** New `qdrant.ts` client (`QDRANT_URL` / `QDRANT_API_KEY`), `@qdrant/js-client-rest` dependency, `worker:embedding` wired into `npm run dev:all`, and a `clear:qdrant` ops script for wiping collections.
