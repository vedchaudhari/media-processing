# 2. Video Data Model

**Status:** ✅ Done

- **Collection:** `videos` (Mongoose model)
- **Status lifecycle:** `uploading → uploaded → inspecting → inspected → planning → planned → transcoding → completed` (or `failed` at any stage)
- **Statuses** defined as `const` array — TS union type & Mongoose enum both derived from it (single source of truth, no drift)

### Schema Fields

| Field | Purpose |
|---|---|
| `title` | User-given video title |
| `objectKey` | MinIO path to original file |
| `status` | Current pipeline stage |
| `progress` | 0–100 transcoding % |
| `metadata` | width, height, duration, fps, codecs, bitrate |
| `variants` | Planned rendition ladder |
| `generatedFiles` | Per-height objectKeys of outputs |
| `streaming` | Master playlist path + variant playlist paths |
| `failedStage` | Which stage failed (inspection/planning/transcoding) |
| `error` | Error message on failure |
| `failedAt` | Timestamp of failure |
