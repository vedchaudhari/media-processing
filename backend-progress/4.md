# 4. BullMQ Job Queue System

**Status:** ✅ Done

> Note: this entry originally covered the 3 core pipeline queues. The
> `thumbnail` and `transcript` queues/workers were added later (entries 13 and
> 14); the counts below reflect the current 5-queue / 5-worker setup.

- **5 queues:** `inspection`, `planner`, `transcoder`, `thumbnail`, `transcript` — each backed by Redis via BullMQ
- **Pipeline chaining:** inspection → enqueues planner → enqueues transcoder (each worker hands off to the next queue on success)
- **Parallel fan-out:** once inspection completes, `thumbnail` and `transcript` are dispatched alongside `planner` (independent, non-blocking)
- **Shared default job options:** 3 attempts with exponential backoff (5s base), auto-cleanup of completed/failed jobs in Redis
- **Dev runner:** `npm run dev:all` uses `concurrently` to launch the API server + all 5 workers in parallel with color-coded logs
