# 21. Cancel Upload (Mid-Transfer)

**Status:** ✅ Done

- **New endpoint:** `POST /api/videos/:videoId/cancel-upload` (`cancelUpload`) — lets the client back out of an upload that's still in the `"uploading"` state.
- **Atomic delete, not a new status:** `Video.findOneAndDelete({ _id, status: "uploading" })` removes the record outright rather than introducing a `"cancelled"` status — since a raw presigned-PUT upload is all-or-nothing in MinIO, an aborted upload never leaves partial bytes behind, so deleting is honest ("as if it never happened") and avoids touching every place that renders the status enum (badges, admin stats/charts).
- **Race-safe against `completeUpload`:** the delete only succeeds if the record is *still* `"uploading"` at update time. If `completeUpload` already won the race, `cancelUpload` loses gracefully and reports the current status instead of deleting a video that's already moved into the pipeline.
- **Best-effort storage cleanup:** checks `objectExists` then `removeObjects` (both pre-existing in `storage.service.ts`) on the object key, covering the narrow race where the PUT actually finished in MinIO a moment before the cancel request arrived.
- **Fixed a latent bug this exposed in `completeUpload`:** its "lost the race" branch assumed `Video.findById` would still return a document; now that a concurrent `cancelUpload` can delete it, that branch returns 404 `"Video was cancelled"` instead of silently reporting `status: undefined`.
