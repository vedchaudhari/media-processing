# 16. AI Chapter Generation

**Status:** ✅ Done

- **Folded into the existing AI job:** Chapters are produced by the same `generate-summary` job (one LLM round-trip), so they share the transcript-completion trigger, the `ai` queue, and the provider switcher — no new queue or job name.
- **Timestamp-aware prompt:** `buildSummaryPrompt` now accepts the transcript `segments` and builds a timestamped transcript (`[start] text` per line). The model is instructed to return 3–8 chapters whose `start` values are copied from real segment start times, ordered ascending, first at ~0.
- **Extended contract:** `SummaryInput` gains `segments`, `SummaryOutput` gains `chapters: { start, title }[]`. `AIService.generateSummary` normalizes `chapters` to always be an array even if a model omits it.
- **All three providers** (Ollama / Gemini / OpenAI) pass `input.segments` into the prompt; response parsing is unchanged (the extra field rides along in the same JSON).
- **Persistence:** `ai.worker.ts` reads `transcript.segments`, passes them to the AI call, and stores results under `aiSummary.chapters`. Added `IChapter` + the `chapters` sub-schema to the `Video` model.
- **Non-blocking sub-state:** Chapters live inside `aiSummary` (same `pending → processing → completed | failed` lifecycle as the summary) and never affect the main `video.status`. Older videos processed before this change simply have no chapters.
