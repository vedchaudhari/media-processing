# 19. Pipeline Reliability Hardening

**Status:** ✅ Done

- **Retry-aware failure marking:** The inspection, transcript, AI, and embedding workers now write their DB `status: "failed"` **only on the final BullMQ attempt** (`attemptsMade + 1 >= attempts`). A transient error on an earlier attempt no longer latches a failed state that would make the polling frontend give up before the retry succeeds.
- **`"skipped"` terminal state:** A silent video (no transcript text / segments) marks `aiSummary` and `vectorIndex` as `"skipped"` — a distinct, non-error terminal outcome — instead of failing or hanging forever in `pending`. The transcript worker also short-circuits the AI/embedding enqueues in that case.
- **Stale-upload sweeper:** `startup/index.ts` runs `failStaleUploads` at boot and hourly, marking records stuck in `"uploading"` past the 1-hour presigned-URL lifetime as `failed` (stage `"upload"`). This stops the library page from polling abandoned uploads indefinitely. Added `"upload"` to the `FailedStage` union.
- **`getPlay` 409 parity:** The not-ready (409) response now returns the same auxiliary fields as the 200 (`thumbnailUrl`, `transcript`, `aiSummary`, `vectorIndex`), so the frontend's "processing" view has the full picture while a video is still moving through the pipeline.
- **DNS override (opt-in, wired but disabled):** `config/dns.ts` can repoint Node's bundled resolver via `DNS_SERVERS` to fix broken corporate/VPN DNS (e.g. `mongodb+srv` SRV lookups failing with `ECONNREFUSED`). The `configureDns()` call currently sits commented-out in `envconfig.ts` — enable it on affected machines.
